# DataGuard Academy — Self-Hosted Lab

A complete, runnable simulation of the data layer at a mid-sized bank. You will:

1. Stand up a realistic Postgres database with customers, accounts, transactions, employees, access logs, and a partially-populated `data_catalog`.
2. Create users and roles with least-privilege permissions (the same way a bank IAM team does it).
3. Run a Python PII scanner against the database — the same logic 1touch.io and Microsoft Purview use under the hood.
4. Walk through the **classification labeling workflow** end-to-end: auto-label → human review → audit → publish.
5. Generate an audit report identifying coverage gaps and anomalous access.

The whole thing runs in Docker. Works identically on **Windows (WSL2)**, **macOS**, and **Linux**. No cloud account, no spend, no PII risk — every record is synthetic.

## Quickstart (5 commands)

```bash
# 1. From the extracted lab folder
cd lab

# 2. Copy the env file (do not edit unless you change ports)
cp .env.example .env        # macOS / Linux / Git Bash
# copy .env.example .env    # Windows PowerShell

# 3. Bring up Postgres + Adminer
docker compose up -d

# 4. Confirm the schema and seed data loaded
docker compose exec db psql -U dga -d dataguard -c "\dt"

# 5. Open Adminer at http://localhost:8080
#    System: PostgreSQL · Server: db · User: dga · Password: dga · Database: dataguard
```

Postgres listens on **localhost:55432** (chosen to avoid clashing with any local Postgres). Adminer is at **http://localhost:8080**.

To stop everything: `docker compose down`. To wipe data and start fresh: `docker compose down -v`.

## What's in the database after `docker compose up`?

| Table | Rows | Purpose |
|---|---|---|
| `customers`              | 500 | Synthetic UK retail customers — names, DOBs, NINOs, emails |
| `accounts`               | ~1,210 | Current/savings accounts with sort codes, IBANs |
| `transactions`           | 25,000 | 12 months of transaction history |
| `employees`              | 60 | Bank staff across 5 departments |
| `access_logs`            | ~8,400 | Who accessed which table, when, for how long |
| `data_catalog`           | partial | The classification register — **only ~15% pre-labeled on purpose** (run the Python toolkit to fill it in) |
| `classification_rules`   | 15 | Regex + context patterns the scanner uses |
| `dsar_requests`          | 12 | Open and closed Data Subject Access Requests |
| `audit_findings`         | (empty) | The scanner writes here |

All data is generated by a deterministic seed — re-running `docker compose down -v && up -d` produces an identical dataset, so quiz answers stay stable.

## The Python toolkit

```bash
# From the lab/ folder
cd python
python -m venv .venv
# Windows / WSL:    source .venv/bin/activate    (or .venv\Scripts\Activate.ps1 on PowerShell)
# macOS / Linux:    source .venv/bin/activate
pip install -r requirements.txt
```

Then run the scripts in this order:

| Script | What it does |
|---|---|
| `01_smoke_test.py`         | Connects to the DB, lists tables, confirms credentials work |
| `02_pii_scanner.py`        | Scans every column metadata + a row sample, flags PII candidates |
| `03_classifier_simulator.py` | Applies `classification_rules` to write labels into `data_catalog` |
| `04_label_review.py`       | Interactive CLI for a human reviewer to accept/reject low-confidence labels |
| `05_audit_report.py`       | Produces a Markdown coverage + access-anomaly report |

Each script is short (≤120 lines), heavily commented, and prints exactly what it changes. **Run them inside the venv with the DB up.**

## Troubleshooting

**`Error: bind: address already in use` on port 55432 or 8080** — edit `.env` to change `DB_PORT` / `ADMINER_PORT`.

**`docker compose: command not found`** — you probably have the legacy `docker-compose` binary. Either install Compose v2 (recommended) or substitute `docker-compose` for `docker compose`.

**Python script fails with `psycopg.OperationalError`** — the DB is not up yet. Run `docker compose ps`; the `db` service should be `healthy` (the healthcheck takes ~10s on first boot).

**WSL: `docker` command works but containers can't reach the internet** — restart the WSL networking layer: `wsl --shutdown` then reopen your terminal.

---

## Reset to a clean state

```bash
docker compose down -v   # delete the Postgres volume
docker compose up -d     # rebuild — schema and seed re-apply automatically
```

Everything in `sql/` runs alphabetically on first DB start, so reordering by filename prefix changes the apply order.
